## Not conforming

- **Dec 3 (amend 08-27, destination nouns):** `ActivityPanel.tsx:54-66` `destinationLabel()` returns verb-prefixed labels ("Open company", "Open sources", …) on `ActionButton kind="destination"` — violates "noun only, no leading Otwórz/Open." Freshly shipped, uncaught by any gate.
- **Dec 3 (amend 08-30, retry classification):** `ActivityPanel.tsx:312` classifies the retry action as `kind="control"`; ADR text says retries must be the dictionary action, never a control.
- **Dec 3 (amend 09-02, visible-label bar):** `ActivityIndicator.tsx:29-46` is an icon-only topbar button whose accessible name comes solely from `aria-label`/`title`, no visible text when idle — exactly the pattern the amendment bans. The existing guard (`expectNamedIconActions`) only checks accessible-name presence, so this class is structurally unguarded.
- **Dec 4 (empty-state invitation):** 15 real screens (including the core Spolka screen, Today screen, Companies/Fundamentals panels) still render bare prose empty states with no action button — `SpolkaScreen.tsx:425,447,500,545`, `CoreKpiTable.tsx:83`, `TodayScreen.tsx:471,656`, `FundamentalsPanel.tsx:604`, etc. Migration is roughly half-done (17 invitation vs 15 legacy).
- **Dec 6 (documents-list row):** `CompanyReportDocumentsPanel.tsx` (the "dokumenty" tool row) leads with the kind label, not necessarily the human title, and has no mono treatment for a raw filename — unlike the Today feed rows (`FilingRow`/`AttentionRow`), which do it correctly.
- **Dec 7 (amend 09-04, one-control thread):** `ProvenanceFigure.tsx` (used live in Inbox/Companies feed-detail context blocks) was not updated to the single-control model — separate non-interactive value + a ticket button with no amendment-format `aria-label`. Only `CoreKpiTable` (Spolka's KPI table) implements the amendment correctly; the codebase now has two diverging implementations of the same ADR decision with no gate to catch the drift.
