# v0.51.0 — Judgment capture: early decision journal + pre-report expectations

Epic: `3242a93` · Design: [ADR 0071](../adr/0071-judgment-capture.md) (decided; amends [ADR 0043](../adr/0043-investment-thesis-and-decision-journal.md)).

Goal: start accumulating the owner's judgment history now — `decision_entries` (immutable journal) and `report_expectations` (written before results, reviewed after). Small milestone, mostly CRUD + read models; the value is that it ships **early**.

## Shapes (from ADR 0071 — STOP-AND-ASK before deviating)

- `decision_entries`: `company_id`, `kind: buy | pass | keep_watching | sell_note`, `rationale_md`, evidence links (typed refs: feed item / report document / note / claim), `decided_at`. **Immutable once saved** — corrections are follow-up entries; no update/delete command (a `superseded_by` link is allowed).
- `report_expectations`: `company_id`, report occurrence (fiscal year + period type, aligning with `report_preparations` from ADR 0044), `stance_md`, optional per-metric rows (`metric_key`, comparator, expected value). Editable **until** the report's facts are confirmed, then frozen; the user's own resolution note is recorded at review.
- Expectation-vs-actual is a **read model** (no stored projection): joins frozen expectations with confirmed `financial_facts` for the period.

## Tasks

### T1 — Migrations + storage
Two append-only migrations; storage modules with typed errors; both entities owner-durable (retention-exempt). Tests: migration corpus, storage round-trips, immutability (no update path compiles/exists for entries).

### T2 — Commands + DTOs
Create/list journal entries (per company + global chronological), create/update/freeze expectations, expectation-vs-actual read command. ts-rs DTOs, mock-runtime router cases, dual-execution fidelity steps. Contracts + data-model docs in the same change.

### T3 — Journal UI
Company-workspace journal section + a global journal list (chronological, filter by kind/company); entry composer (kind, Markdown rationale, evidence picker reusing the research-evidence link picker); entries join the company research timeline. Primitives only; empty states; narrow-viewport assertion.

### T4 — Expectations in the report-season flow
Pre-report card (ADR 0044 cockpit) gains "write expectations" (stance + optional metric rows with metric-key picker from the company's relevant KPIs); after facts confirm, a review surface shows expectation-vs-actual side by side and records the user's resolution note. Autopilot cross-reference stage links the review into the run notification when expectations existed.

### T5 — Journeys + tests
Journey spec updates: J4 gains the expectations step, J6 becomes implementable — add/extend `tests/browser/journeys/` specs with step budgets (first measurement calibrates the numbers in `ux-journeys.md`). Vitest workflow tests for composer and review; Rust read-model test where `created_at` order ≠ domain-date order (DoD §C guardrail).

### T6 — Closure
Import/export note: entities are **exported from v0.52** (unified bundle) — record as an explicit v0.52 dependency, not silent scope creep here. Docs closure, retro with UX section, real use by the owner on ≥1 upcoming report before sign-off.

## Tripwires
- Any automated scoring/verdict of the user's judgment ⇒ STOP (the app mirrors, never grades — ADR 0071).
- Temptation to add thesis fields ⇒ STOP (that is v0.64; the table must stay extension-ready, not pre-extended).
