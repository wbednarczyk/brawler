# v0.52.0 retrospective — judgment capture + MCP MVP + embedding-model retirement

Written at closure (2026-07-12), before release sign-off. Domains: the app and the development loop; each item marked **closed** or **still-open** honestly — the owner decides what needs action.

## App

### Went well
- **Judgment capture landed whole**: immutable journal (DB triggers, not convention), freeze-in-transaction expectations, expectation-vs-actual as a factual mirror (never grades), reachable end-to-end — J6 "buy/pass decision" is now a real, budget-measured journey (11 interactions), not a spec placeholder. **closed**
- **MCP MVP proved the second-driving-adapter posture** (ADR 0039): four read-only tools bound directly to existing read models, zero new ports, protocol module fully unit/property/snapshot-tested, and the final proof was a **real Claude Code client** returning a live dossier over Streamable HTTP with bearer auth. **closed**
- **The retirement paid immediately**: −57 crates, portable exe −3.3 MB, −4300 LOC net, and the cross-build got faster; forward migrations snapshot-tested against a seeded old-state DB. **closed**
- Scope-growth-instead-of-renumbering kept Radicle labels, plan filenames, and the roadmap consistent in one pass. **closed**

### Went wrong / unexpected
- **ADR 0080's deletion list was almost too literal**: `entity_resolution.rs` was only half-dead — its text-normalization helpers had live consumers in feed/company matching. The R1 agent caught it via `repoctx callers` before deleting (tripwire near-miss) and relocated the live half with its proptests. Lesson: a removal ADR should name the *symbols* to remove, not the *files*. **still-open** (rule candidate for the next removal ADR)
- **Spec drift had accumulated silently around the owner decision**: the 2026-07-06 MCP decision lived only in an epic comment; the roadmap was never updated, and the pre-planned "renumber +1" note contradicted what the board actually held. The planning pass burned real time reconciling three sources of truth. **closed** for this milestone (roadmap now canonical again); **still-open** as a class — owner decisions made in Radicle comments need a same-day roadmap edit.
- Judgment entities ship **without bundle export coverage** until v0.67 (deliberate deferral; whole-DB rotating backups cover safety). **still-open by design** — recorded in the plan and ADR.
- The dossier tool exposes only a **capped confirmed-facts slice** and current scorecards; richer research context (notes, claims content) flows through search/claims tools. Whether that composition satisfies real assistant conversations is untested with real usage. **still-open** — feeds the NS1 chat slice.

## Development loop

### Went well
- **The wave model held**: 7 waves, ≤3 delegated slices each, every slice a written contract with enumerated tests-that-redden and pasted red evidence; every wave closed behind `make check-fast` or the full gate; three squash-ready commits, each with the pre-commit gate as proof.
- **Cross-agent coordination on one tree worked** when contracts named the shared files and the add-only/remove-only rule (Cargo.toml, `generate_handler`): M1/M2/R1 landed concurrently without a single merge casualty; M3 reconciled M4's provisional mock instead of duplicating it.
- **Guardrail harvest ran continuously, not at closure**: five classes closed mid-milestone (disk/vhdx guard in the gate; env-fallback scrub for hermetic tests; proxy-await rule; free-port probe rule; api-surface-guard for UI-unwired wrappers) — each from a real red, each with a gate or documented rule.
- **Real evidence culture**: C1 diagnosed against a read-only copy of the owner's live DB; M5/closure verified MCP with curl + the stdio pipe + a real Claude client; R1's migrations were tested against seeded old-state data.

### Went wrong / unexpected
- **Environment killed the loop twice**: a full host C: (WSL vhdx growth — invisible from inside WSL) and session usage limits each killed three in-flight agents mid-slice. Recovery worked (transcripts + tree state + resume messages), but red-first evidence was occasionally lost to the crash and had to be re-derived. Disk class **closed** (disk-guard watches `/mnt/c`); session-limit class **still-open** (no mitigation beyond resume discipline).
- **Latent test hermeticity debt surfaced under the new load**: three pre-existing test classes (env-fallback credentials, fixed/clamped ports, proxy-await races) had passed for weeks by luck and reddened only when this milestone's parallelism and my shell's env hit them. All three **closed** with rules + fixes, but the pattern suggests a periodic "run the suite from a hostile environment" sweep. **still-open** (candidate for the failure-path test epic `0db7a7a`).
- **The L1 doc byte budget was at 34 bytes of headroom** when a mandatory-read guardrail needed a paragraph — forcing a deliberate +1 KiB raise (ADR 0063 note). Budget pressure is working as designed, but the headroom exhaustion was invisible until a gate run failed at the finish line. **still-open** (cheap idea: gate-integrity could warn at <5% headroom instead of only failing at 0).
- **Fidelity corpus and platform truth**: keychain persistence differs between the Linux mock backend and real Windows, so the MCP token journey deliberately asserts only the platform-independent intersection. Honest, but it means the real keychain round-trip is only covered by the opt-in live keyring smoke + owner dogfooding. **still-open by design**.

### Stop doing
- Writing removal scopes as file lists (see entity_resolution) — name symbols + their expected caller count instead.
- Letting owner decisions live only in Radicle comments — same-day roadmap edit or it drifts.

### Improve next milestone
- Add a "hostile environment" nightly-style sweep (exported fake provider keys, occupied default ports, non-UTC timezone) to the failure-path epic.
- gate-integrity headroom warning for ADR 0063 budgets.
- Consider naming expected-symbol-consumers in deletion ADRs (the R1 lesson) as a standing rule in the guardrail-harvest skill.

## Dogfooding rounds (addendum, post-retro)

Two owner dogfooding rounds ran after this retro was first written; per the owner's rule all findings were fixed in-milestone:

- **Round 1**: raw native date input (→ new `DateField` primitive, adopted app-wide); **P1** — first real journal entry failed on `evidence_type: decision_entry` (the allowed-types list and the reference-resolution `match` were two separate exhaustive lists; fixed + latent `company_signal` sibling + a structural test that walks every allowed type); add-panel palette enumerated every tracked company (→ generic panel types bound to the view company). **closed**
- **Round 2**: palette still enumerated per-company "Switch view company" entries (→ removed; the header selector is the single retarget surface) and the palette search rendered as a bare native input (→ `search-box` class; guardrail: ui-authoring.md now requires a styling `className` on `SearchField` call sites). **closed**
- **MCP from WSL** initially failed (NAT networking); solved by enabling **mirrored networking** in `.wslconfig` — Settings and the wiki now say where to add the server (Windows vs WSL). **closed**
- Loop lesson: the P1 escaped every gate because both lists individually looked complete — the harvested class is "one allowed-values list, one dispatcher, one structural test that ties them". Also: closure artifacts (this retro, guardrails, audits) are **presented inline in chat** before commit — a committed file the owner never saw does not count (now a release-skill step). **closed**
