# v0.54.0 — Attention routing: toasts, alert rules, morning briefing

Epic: `5bc40a8` · Design: [ADR 0068](../adr/0068-attention-routing-and-morning-briefing.md) (decided) · Signals: [ADR 0034](../adr/0034-espi-event-classification.md) · Autopilot events: [ADR 0055](../adr/0055-autonomous-report-pipeline-trust-ladder.md).

Goal: the app tells the user what deserves attention — `Toast` primitive, user-owned alert rules, and a cited morning briefing on Today. In-app only; the boundary is shaped for later OS adapters.

## Shapes (from ADR 0068 — STOP-AND-ASK before deviating)

- **`Toast` primitive** in `src/ui` (ADR 0037): transient variant (async action feedback, auto-dismiss) + persistent variant (attention events, explicit dismiss, click-through to evidence). One global toast region in the app shell; no screen renders its own.
- **`alert_rules` entity**: `trigger` (signal category | autopilot run completed | price condition: `enters_range(min,max)` / `week52_low`), `scope` (company | watchlist), `enabled`. Price conditions evaluate against `daily_quotes` (v0.53) on each daily pull.
- **Attention events**: emitted by rule evaluation, persisted (`attention_events`: rule, company, evidence ref, fired-at, seen/dismissed), consumed by the toast region and a Today attention list. Dedup: one event per (rule, evidence); no re-fire on re-ingest.
- **Morning briefing**: a job composing a deterministic item list (new signals since last briefing, autopilot runs, claims due, upcoming report dates, fired alerts) + an AI-phrased narrative with citations via a `ResearchDigest`-style capability call; **with no provider configured the briefing still renders as the structured list** (narrative absent, never blocked). Surfaced as a Today card; on-demand button + once-per-day auto refresh while the app is open.

## Tasks

### T1 — Toast primitive
`Toast` + `ToastRegion` in `src/ui` (both variants, queueing, a11y: `role="status"`/`aria-live`), gallery + `primitives.test.tsx` + a11y suite (DoD §B). Shell integration.

### T2 — Rules + events backend
Migrations (`alert_rules`, `attention_events`); storage + typed errors; rule evaluation hooked into: signal ingestion (post-classification), autopilot `finalize_notify`, and the post-daily-pull price check. Dedup + a per-rule daily throttle. Worker-lane decision: evaluation is cheap — runs inline in those job stages, no new lane. Tests: evaluation unit tests per trigger type, dedup/no-re-fire tests, deterministic pipeline test extension.

### T3 — Commands + rules UI
CRUD commands for rules + list/dismiss for events (DTOs, mock-runtime, fidelity steps). Settings/company-workspace rules manager (visual-first per ui-authoring: preset rule chips + scope picker; price-range inputs with two-way binding). Contracts/data-model docs same change.

### T4 — Attention surfaces
Persistent toasts for fired events (click-through to the evidence: signal item, run card, quote context); Today attention list (grouped by company, seen/dismiss). Narrow-viewport assertions.

### T5 — Morning briefing
Briefing job (deterministic composer + optional narrative via the capability pool; store both), Today briefing card (narrative with citation links, or structured list), on-demand + daily trigger. Tests: composer golden snapshot, no-provider path test, citation-integrity test (every cited id exists in the composed list).

### T6 — Toast adoption sweep + closure
Replace inline-only async feedback with transient toasts on the highest-traffic actions (refresh, save, import/export, AI job start/finish) — sweep, not rewrite; inline errors stay where they are the right UX. Journey: J1 gains the briefing entry step — update `ux-journeys.md` + J1 journey spec budget. Docs closure + wiki; real use: owner runs a morning with real data before sign-off.

## Tripwires
- OS/desktop notifications ⇒ STOP (out of v1 scope; boundary only).
- Alert copy drifting into advice ("consider buying the dip") ⇒ STOP — facts + links only.
- Briefing narrative without citations validating against the composed list ⇒ STOP (never store uncited narrative).
