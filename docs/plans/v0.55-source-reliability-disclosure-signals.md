# v0.55.0 — Source reliability & disclosure signals

Epic: `ad9d24f` · Design: [ADR 0069](../adr/0069-source-reliability-and-disclosure-signals.md) (decided) · Taxonomy base: [ADR 0034](../adr/0034-espi-event-classification.md).

Goal: give the SourceAdapter port real behavior (`Fetcher` trait), re-enable GPW ESPI/EBI as a reconciliation second witness (closing the Bankier SPOF), add the KNF short-selling registry adapter and the auditor-opinion/going-concern signal.

## Shapes (from ADR 0069 — STOP-AND-ASK before deviating)

- **`Fetcher` trait** beside the descriptor (registry stays a const catalog): `fetch(&self, ctx: &FetchContext) -> Result<Vec<RawSourceItem>, FetchError>`; `source_refresh` dispatches by adapter id → registered fetcher. `RawSourceItem` is the normalized pre-pipeline shape already produced by adapters today (verify the current internal type and reuse it — do not invent a parallel one).
- **Reconciliation**: ESPI items matched to Bankier-sourced reports by (company, disclosure date, report type/number); results persisted per pair (`matched | bankier_only | espi_only`); mismatches feed developer diagnostics + a source-health warning. Witness role only — ESPI items do **not** enter the Inbox while Bankier remains primary.
- **KNF short registry**: `disclosure`-type adapter; per-company net-short entries (holder, size %, date) with history; `short_position_change` typed signal on new/changed entries.
- **Auditor signal**: `auditor_opinion` rule-classifier category (qualified opinion / disclaimer / going-concern emphasis) over filing title+category+body; AI fallback keeps confirm-before-apply (ADR 0034 semantics).

## Tasks

### T1 — Fetcher trait + strangler migration
Introduce the trait + registration; migrate **two** existing adapters (Bankier RSS, GPW market events) to prove the shape; `source_refresh` gains the polymorphic path while unmigrated adapters keep their arms (tracked list in code comment). Tests: existing source-refresh suites stay green (behavior-preserving refactor), one dispatch unit test. **STOP-AND-ASK if the trait forces async/signature changes that ripple into the queue contract.**

### T2 — Remaining adapter migrations
Migrate the rest (Bankier per-company, calendars, directories) adapter-by-adapter, deleting `source_refresh` branching as it empties. Golden ingestion tests per adapter (sample bytes → items) pin behavior across the move.

### T3 — ESPI second witness
Re-enable `gpw-espi-ebi` in witness mode (new visibility/role field on the descriptor — normal-user Sources UI shows it as a health mechanism, not a feed); reconciliation job + persisted pair results; diagnostics panel section + source-health surfacing. Tests: match/mismatch/miss fixtures, no-Inbox-leak test.

### T4 — KNF short-selling adapter + signal
Fetcher-based adapter over the public register (verify the current KNF publication format at implementation — CSV/HTML; **STOP-AND-ASK if only a viewer UI without a stable data path exists**); history storage; `short_position_change` signal + feed badge/filter + company readout; alert-rule trigger compatibility (v0.54) verified.

### T5 — Auditor-opinion signal
Rule patterns (Polish phrasings: "opinia z zastrzeżeniem", "odmowa wyrażenia opinii", "kontynuacja działalności" emphasis) + tests over real filing-title fixtures; category joins badges/filters/digests/alert rules. Real-data check: run the classifier over the maintainer's stored filings, review hits before enabling by default.

### T6 — Closure
Docs: source-strategy adapter sections updated from "planned" to live, contracts/data-model for new entities/commands, ADR 0050 note already points here. Journeys: J1 (new signal categories in triage). Retro incl. "did the Fetcher migration leave any bespoke branching".

## Tripwires
- Weakening a golden ingestion test to make an adapter migration pass ⇒ STOP (behavior-preserving means byte-level same items).
- ESPI witness tempting into dual-ingestion (items entering the feed twice) ⇒ STOP.
- KNF scraping beyond a stable public data path ⇒ STOP (source policy).
