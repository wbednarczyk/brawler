# v0.56.0 — Ownership structure: stakes, history, classification, free float

Epic: `7e0b7c1` · Design: [ADR 0072](../adr/0072-ownership-structure.md) (decided) · Extraction semantics: [ADR 0061](../adr/0061-deterministic-fundamentals-data-gathering.md) · Signals: [ADR 0034](../adr/0034-espi-event-classification.md).

Goal: `ownership_stakes` as a first-class, automatically gathered, time-aware entity — extraction from stored periodic reports, the major-holdings ESPI signal, aggregator witness, holder-type classification, derived free float, donut + stake-over-time presentation.

## Shapes (from ADR 0072 — STOP-AND-ASK before deviating)

- `ownership_stakes`: company, normalized holder name, holder type, **capital % and votes % separately**, `as_of` date, source (`report_document | espi_filing | aggregator | manual`), provenance links. Append-only snapshots per (source, as-of); history is the product.
- Holder types: `founder_insider | family_foundation | tfi | ofe_pension | state_treasury | parent_company | treasury_shares | other_institutional | free_float_rest`. Deterministic name dictionary first (TFI/OFE/PFR lists are enumerable — seed as data, not code), AI fallback with confirm-before-apply.
- `major_holdings_change` signal category (ESPI threshold notifications) — classified deterministically (these filings are formulaic), updates stakes after the standard confirmation semantics for AI-assisted parses.
- Free float = 100% − Σ disclosed stakes, always shown with the uncertainty note.
- **Real-data-first rule (ADR 0061 heritage + testing.md): the report-table extraction approach must be validated against a hand-labeled ground-truth set from the maintainer's stored reports BEFORE committing to the parse design** — this is the milestone's riskiest part.

## Tasks

### T1 — Extraction spike with ground truth (gate for the rest)
Hand-label the shareholders table for ~15 maintainer-tracked companies (varied formats); prototype deterministic extraction over the already-stored report documents (reuse `report_diff/extraction.rs` section splitting); measure recall/precision. **Outcome decides the tier split (deterministic vs AI-with-confirmation share) and is reported to the owner before T2.** `#[ignore]` harness in the real-data suite, mirroring `real_data_extraction.rs`.

### T2 — Data model + storage
Migrations (`ownership_stakes`, holder dictionary seed table); storage with typed errors; owner-durable (import/export section added to the v2 registry). Tests: migration corpus, round-trips, snapshot-append semantics (same source+as_of upserts, never rewrites history).

### T3 — Ingestion stream 1: report extraction
Extraction job over stored periodic reports (backfill pass + on-new-report); deterministic parse per T1's design, AI fallback with mandatory confirmation for the residual; provenance to the exact document. Golden + proptest no-panic on the parser; deterministic pipeline test.

### T4 — Ingestion stream 2: ESPI signal + stream 3: witness
`major_holdings_change` classifier rules + tests over real filing titles; stake updates from confirmed notifications. Aggregator witness (BiznesRadar/Bankier Akcjonariat pages — via `Fetcher`): compare-only job flagging divergence in diagnostics; never writes stakes.

### T5 — Classification
Dictionary seed (TFI/OFE/state entities) + normalization (legal-form suffix stripping); AI classify-with-confirm for unknowns; manual re-type always available. Tests: dictionary hit tests, normalization property tests (idempotence).

### T6 — UI
Company-workspace ownership section: current-state donut (grouped by holder type, free float slice with uncertainty note) + stake-over-time chart per holder with threshold-event markers (dataviz skill at implementation; reuse chart primitives, add one if genuinely missing — ADR 0037 process). Commands/DTOs/mock-runtime/fidelity; narrow-viewport assertion; empty state (no disclosures yet).

### T7 — Closure
Free float exposed where relevant (company header/metadata); red-flags/v0.57 gets its fund-exit feed from here (interface note, no v0.57 code). Docs closure (contracts, data-model, source-strategy live sections, wiki). Journeys: J3 (auto-populates on onboarding). Real-data validation evidence in the epic before sign-off.

## Tripwires
- T1 metrics poor (recall <80% deterministic) and temptation to ship AI-only extraction without confirmation ⇒ STOP (never silently wrong).
- Rewriting historical snapshots on re-ingest ⇒ STOP (append-only is the contract).
- Votes % conflated with capital % anywhere ⇒ STOP (the gap is the signal).
