## Reconnaissance (current state)

- **`evaluate_framework` does NOT filter by `kind`** ([storage/quality_frameworks.rs:751](../../src-tauri/src/storage/quality_frameworks.rs#L751)). A qualitative criterion has empty `expression`; `evaluate_criterion("")` → `parse` fails → `Verdict::Unavailable`. So a quant run writes a **phantom `unavailable` engine row** for every qualitative criterion. This is a composition gap to fix (not a quant-semantics change — real quant criteria unaffected).
- **T4** persists **qual-only** snapshots (`source = agent`) via `persist_qualitative_assessment`. **T5** panel already composes the current-state view: latest quant snapshot + `get_qualitative_assessment` (most-recent agent row per criterion across snapshots — ADR Decision 5 "two read surfaces").
- **No verdict-change detection** exists anywhere for frameworks. Closest analogs: `report_diff/diff.rs` (`diff_sections`), research "changed-since-review" flags in `storage/research_digests.rs`.
- **Autopilot does NOT run frameworks at all.** Pipeline `fetch → extract → diff → cross_reference → notify` ([jobs/autopilot.rs:29](../../src-tauri/src/jobs/autopilot.rs#L29)). `stage_cross_reference` cross-references new reports against open claims + research questions only — never frameworks. Only caller of `evaluate_framework` is the Tauri command. Trust ladder (`off|assist|autopilot`, `storage/autopilot.rs`) gates acceptance, not stage execution.
- **`enqueue_assessment(state, company, framework, criterion_ids?)`** ([commands/quality_frameworks.rs:222](../../src-tauri/src/commands/quality_frameworks.rs#L222)) — idempotent, one job row per `company:framework`, merges pending requests. This is the re-enqueue seam for D3.

Unit of content is `ResearchEvidenceItem` with a free-string `evidence_type` (synthetic `"reminder"` already exists). Verdict-change lines append inside `collect_research_digest_evidence` (~[storage/research_digests.rs:270](../../src-tauri/src/storage/research_digests.rs#L270)).
- **No framework↔company assignment model.** The only source of "which pairs to refresh" is existing `framework_evaluations` snapshots.
- Template model: `TemplateCriterion` ([fundamentals/templates.rs:14](../../src-tauri/src/fundamentals/templates.rs#L14)) is quant-only (label + expression + partial_band). `insert_criterion` / `seed_template_criteria` already accept `kind` + `assessment_guidance`; `seed_template_criteria` currently hardcodes `"quantitative"`.

## Design decisions (recommendations)

- **D1 — "Combined snapshot" = composed read view, NOT one physical row.** Quant is sync (command), qual is async (agent job); forcing one `framework_evaluations` row means quant waits on the agent or the agent mutates an immutable snapshot. The two-read-surfaces design exists precisely because snapshots are separate. **Keep snapshots separate; fix `evaluate_framework` to skip qualitative criteria; add a current-state composition read (quant-latest + qual-most-recent).** Aligns with ADR 0075 Decision 5. (Recommended — high confidence.)
- **D2 — Change detection:** a read `qualitative_verdict_changes(framework, company)` computing per-criterion `previous agent verdict → current agent verdict`, consumed by digest (D4) and autopilot notify.
- **D3 — Autopilot re-enqueue scope (OPEN — needs owner confirm):** on new-report arrival, for the company in `assist`/`autopilot` mode, re-enqueue `qualitative_assessment` for each framework that **already has a prior agent assessment for that company** (bounded, meaningful — refresh existing assessment on new evidence). `off` never auto-runs. Wire into the existing pipeline (extend `cross_reference` / detection sweep), no full new stage — assessment runs as its own durable job.
- **D4 — Digest:** synthetic `ResearchEvidenceItem` (`evidence_type: "framework_verdict"`) for verdict changes, company scope.
