# v0.50.0 — Quality frameworks: qualitative assessment

Epic: `5835112` · Base: [ADR 0046](../adr/0046-quality-frameworks-quantitative.md) (quantitative frameworks, shipped v0.44) · Routing: [ADR 0060](../adr/0060-ai-capability-routing-and-openai-compatible-provider.md) · Existing Radicle tasks `a0a57ab b471dfd a10faeb 82e64e1 910d39a` map to §T1–§T7 below.

Goal: agent-assessed qualitative criteria (moat, pricing power, recurring revenue, capital allocation…) with citations, composed into the existing versioned scorecard and re-evaluated by autopilot.

## Pre-decided design (ratify in §T1's ADR; STOP-AND-ASK before deviating)

- **Criterion model**: `framework_criteria` gains `kind: quantitative | qualitative`. Qualitative criteria carry `assessment_guidance` (owner-authored prompt seed, per criterion) and no DSL expression. Existing quantitative rows are untouched (`kind` defaults to `quantitative` via a backfilling, idempotent migration).
- **New AI capability `QualitativeAssessment`** in the ADR 0060 capability map (text-capable pool; falls back to the general provider). One request **per criterion per company** — small, citable, retryable — not one mega-prompt per framework.
- **Evidence scope**: the prompt is grounded in app-held sources only — stored report documents (latest periodic + annual), research evidence links, claims and their verdicts, recent typed signals, notebook notes. No web access. Every request lists the evidence identifiers it was given; the response must cite them.
- **Result shape** (`criterion_results` extension): `verdict: pass | partial | fail | insufficient_evidence`, `reasoning` (short), `citations` (typed evidence refs — reuse the research-evidence reference model), `confidence: low | medium | high`, `prompt_version`, `source: agent`. **No user confirmation gate** (results are labeled agent opinion, not facts — unlike KPI extraction), but results are visually distinct, regeneratable, and never mutate quantitative data.
- **Scorecard composition**: agent results merge into the same immutable evaluation snapshot with per-criterion `source`; a snapshot records the prompt versions used. Change detection compares verdicts against the previous snapshot; changes surface in digests and on autopilot re-evaluation (assist/autopilot rungs re-enqueue assessment on new-report arrival; `off` never auto-runs).
- **Decision-support hard rule**: prompts forbid and tests assert no buy/sell/hold or allocation language in stored reasoning.
