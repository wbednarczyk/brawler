# v0.50.0 — Quality frameworks: qualitative assessment

Epic: `5835112` · Base: [ADR 0046](../adr/0046-quality-frameworks-quantitative.md) (quantitative frameworks, shipped v0.44) · Routing: [ADR 0060](../adr/0060-ai-capability-routing-and-openai-compatible-provider.md) · Existing Radicle tasks `a0a57ab b471dfd a10faeb 82e64e1 910d39a` map to §T1–§T7 below.

Goal: agent-assessed qualitative criteria (moat, pricing power, recurring revenue, capital allocation…) with citations, composed into the existing versioned scorecard and re-evaluated by autopilot.

## Pre-decided design (ratify in §T1's ADR; STOP-AND-ASK before deviating)

- **Criterion model**: `framework_criteria` gains `kind: quantitative | qualitative`. Qualitative criteria carry `assessment_guidance` (owner-authored prompt seed, per criterion) and no DSL expression. Existing quantitative rows are untouched (`kind` defaults to `quantitative` via a backfilling, idempotent migration).
- **New AI capability `QualitativeAssessment`** in the ADR 0060 capability map (text-capable pool; falls back to the general provider). One request **per criterion per company** — small, citable, retryable — not one mega-prompt per framework.
- **Evidence scope**: the prompt is grounded in app-held sources only — stored report documents (latest periodic + annual), research evidence links, claims and their verdicts, recent typed signals, notebook notes. No web access. Every request lists the evidence identifiers it was given; the response must cite them.
- **Result shape** (`criterion_results` extension): `verdict: pass | partial | fail | insufficient_evidence`, `reasoning` (short), `citations` (typed evidence refs — reuse the research-evidence reference model), `confidence: low | medium | high`, `prompt_version`, `source: agent`. **No user confirmation gate** (results are labeled agent opinion, not facts — unlike KPI extraction), but results are visually distinct, regeneratable, and never mutate quantitative data.
- **Scorecard composition**: agent results merge into the same immutable evaluation snapshot with per-criterion `source`; a snapshot records the prompt versions used. Change detection compares verdicts against the previous snapshot; changes surface in digests and on autopilot re-evaluation (assist/autopilot rungs re-enqueue assessment on new-report arrival; `off` never auto-runs).
- **Decision-support hard rule**: prompts forbid and tests assert no buy/sell/hold or allocation language in stored reasoning.

**As-built (T4), for T6 composition:**
- Each job run persists a **qualitative-only snapshot** (`framework_evaluations` + `criterion_results`, `source = agent`) — the ADR Decision 5 qual-only case. `period_id` is NULL (assessment is company-level, not period-scoped); `engine_version` pins the shared snapshot schema version (agent provenance lives per-criterion in `prompt_version`). `insufficient_evidence` counts into `unavailable_count` (the quantitative "could not determine" bucket). T6's combined snapshot composes over this same write path (`persist_qualitative_assessment` in `storage/quality_frameworks.rs`).
- The provider call is `complete_document` with an **empty `Text` document** — the T3 prompt is self-contained (evidence embedded via `evidence_block`); the marker the test-sample branches on (`QUALITATIVE_ASSESSMENT_MARKER`) is a verbatim prefix of that prompt (no separate wire string to drift).
- Citation validation lives in the job (`validate_and_serialize_citations`): every citation must resolve to a supplied `(evidenceType, evidenceId)`; a `pass`/`partial`/`fail` verdict must carry ≥1 citation, `insufficient_evidence` may carry none. **All-or-nothing per run** — any invalid criterion response fails the whole job (queue retry), so an uncited/partial snapshot is never stored. (Reviewed: the atomic tradeoff was kept deliberately over per-criterion skip, so history stays clean; the two most common spurious-failure causes were removed instead — see next bullet.)
- **T4 code-review fixes applied:** an empty qualitative-criteria set is a clean `Ok` no-op (not a retried-to-terminal failure); the parser tolerates empty `reasoning` for `insufficient_evidence` (decisive verdicts still require it); the completion log uses the persisted evaluation's ids + assessed count (no more `companyId=ok` / wasted query); the shared evidence-ref set + request evidence are built once per run, not per criterion; the test-sample branch keys on `QUALITATIVE_ASSESSMENT_MARKER` (single source). **Discovered in T2 (must close here):**
- **Mock fidelity for criterion kind/guidance.** The mock-runtime `create_framework_criterion`/`update_framework_criterion` handlers must mirror the storage validation (qualitative requires non-empty guidance; quantitative validates the DSL predicate on the *effective* expression, incl. a qualitative→quantitative switch) so dual-execution fidelity holds.

**Discovered in T4 code review (must close here — latent until T5 wires the trigger):**
- **`QualityPanel` current-state read must NOT be the latest snapshot.** The panel reads `list_framework_evaluations` and takes `rows[0]` (latest by `created_at`). A qual-only snapshot (T4) would become "latest" and hide the quantitative scorecard (and a single-criterion re-run would show a one-row snapshot). T5 must wire the panel to `get_qualitative_assessment` (most-recent agent row per criterion across snapshots) per ADR 0075 Decision 5 "two read surfaces" — the existing latest-read is a landmine the moment `run_qualitative_assessment` is reachable.
- **`CriterionVerdict` ts-union must gain `insufficient_evidence`.** The generated union is still `pass|partial|fail|unavailable`; agent rows now store `insufficient_evidence` (the Rust field is a raw `String`, so nothing enforces it). Extend the union (or add a sibling) before surfacing agent rows, else TS consumers conflate it with `unavailable`. ADR 0075 deferred this to a T2/T5 DTO detail; the value is now reachable in stored data.
