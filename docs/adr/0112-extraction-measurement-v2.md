# ADR 0112: Extraction Measurement v2 — Sound ESEF Regression Floors

Status: Accepted (2026-09-12, owner decisions on the three estimand questions; PR-A tooling + protocol, PR-B measurement + floors — #331 stays open until PR-B lands)

Amends [ADR 0095](0095-retire-html-positional-tier.md) decision 4 (v2 is ESEF-only) and [ADR 0096](0096-quality-gate-architecture-under-continuous-release.md) (the #182 scorer's "diagnostic until v2" consequence). Reconciles [ADR 0100](0100-two-layer-tagged-fact-capture-and-ifrs-vocabulary.md) §7 (comparatives are captured, not projected — measured, not amended) and its basis-preservation requirement (measured, not amended). Shares the corpus registry and ground-truth format with epic #355 (roadmap E4) without duplicating its acquisition estimand.

## Context

The #182 measurement (2026-08-05) found five real defects but the methodology audit ruled its numbers unsound as floors: the scorer graded facts already stored in a snapshot, the corpus was chosen from what the pipeline had already extracted, matching ignored dimensions, no estimand was named, positional documents were CD Projekt-heavy, adjudication was not blinded. ADR 0095 retired the positional tier; `make check-epic` / `realdata-gt-check` were retired by ADR 0096. Two peer-review rounds on the v2 plan (2026-09-12) corrected further premises: owners-of-parent concepts ARE supported through their own metric keys (`wdf_equity_parent`, `wdf_net_profit_parent`, ADR 0100 reuse-before-mint); the production `Tolerance` (0.5 % / 1 base unit) is an identity-check allowance, not an equality rule; a valid iXBRL instance always derives `period_type = FY` today (`jobs/structured_extraction.rs` `derive_report_period_uncached`) — a genuine interim iXBRL would be stored as an annual; the v1 reference labeler read only the first ZIP member, judged duplicates without value agreement, looked up `segment` under `context` instead of `entity`, and its merger stamped every row `consolidated`.

## Decisions

1. **Estimand pair.** The **floor** is **cold-start extraction per canonical filing event**: an event = one filing file — a whole ESEF package or a loose instance — for (issuer, fiscal period, reporting vintage), role `floor`, `twin_diagnostic` or `warmup`; every package member is labeled with its own language and basis, members in the pinned (Polish) language are the floor population and other-language members inside the same package form the within-package twin-diagnostic population; each `floor` event is extracted alone into a fresh migrated database through the production path (`derive_report_period` → `run_structured_extraction`, autopilot mode) and its persisted Layer 2 facts are scored. The derived period is recorded next to the independently labeled one — a wrong derivation keeps the event and scores its slots as misses. **Issuer replay** (the issuer's warm-up + floor events in domain-date order into one database, scored after each event) is a printed diagnostic, never a floor; it reports how many events exercised the prior cross-check and the history quarantine (counted only for events that ran to a persisted outcome with the inputs present) and `replay_matched` (non-negative; the delta is derivable). Polish is the floor language; an English twin in a separate file is a `twin_diagnostic` event, an English member inside the same package a twin-diagnostic population — both feed the twin-agreement rate, neither a floor denominator; a member whose language cannot be read from the filing stays `unknown` (queued for a read, excluded from every floor denominator, never inherits the event's language). Restatements are vintages, never a `variant` token.
2. **Scoring key = `(event_id, fiscal_year, period_type, semantic slot)`** with `semantic slot = (concept, attribution, basis, window, variant)`, produced from both sides by the versioned `scripts/realdata/esef-v2/gt_key_map.json` (concept ↔ `(metric_key, attribution)`; structured writes stamp `attribution = total`, so parent-attributed concepts map through their own keys). Raw storage identity is retained and asserted per prediction: `data_quality == final`, stored `period_end` equals the labeled date. Expected `window` comes from the labeled context under the frozen convention (instant → `point_in_time`, cumulative duration → `flow`) and is compared with the **stored** column; basis and variant likewise. **Value equality is exact normalized decimal** with currency mandatory — the production `Tolerance` is not used.
3. **Contract-normalized layer** = the enumerated transformations in the key map (cumulative-context → `flow`, cash-flow outflow sign), each with a machine-readable scope (`scope`/`concepts`) that the labeler and the harness read from the same file — one predicate on both sides, no hard-coded list on either. `BASIS_MISMATCH`, `WINDOW_MISMATCH`, `VARIANT_MISMATCH`, `PERIOD_DATE_MISMATCH` are never normalized. The **sensitivity score** recomputes recall/precision with the convention-resolved population removed from both sides (misses stay misses); an empty strict population prints "not measurable".
4. **Ground truth v2 = immutable occurrences, derived slots.** `occurrences_v2.json` keeps one row per iXBRL fact occurrence with its full evidence (package member, entity, expanded concept, context, period, unit, decimals/scale/sign/format, dimensions, raw text, parse status); `ground_truth_v2.json` slots list their contributing occurrences. Every slot carries its iXBRL `unit`; `currency` is the unit's monetary numerator and is `null` for shares/pure units (such slots count for labeled capability only, and a non-monetary answer in adjudication is validated by the task's unit). Occurrences with an unresolved context, unit or transform stay in the evidence file as `parse_status: unparsed` and never abort a run. Duplicates are one slot only when concept, dimensions, period, unit, currency and value agree; otherwise `unverified` until adjudicated. `basis`, `language`, `attribution` may be `unknown` with evidence, never manufactured. The v1 merged rows import as `verification: machine_v1` and are excluded from floors until re-verified.
5. **Denominators — three named numbers, never blended.** (a) **Current-period slot recall** = matched floor-event GT slots on the frozen panel / all such GT slots; **labeled-scope precision** = correct predictions / all predictions attributable to the event and a panel concept — matching is one-to-one (eligible slots first: exact matches, then deterministic mismatch pairing by concept → fiscal period → fewest differing dimensions → stable id order; only afterwards may `unverified`/`machine_v1` slots claim leftover predictions, and only by full identity); a paired-but-wrong prediction counts against precision and its GT slot stays a miss; unpaired predictions inside the panel/event are false positives; predictions outside are listed as out of scope, unscored. (b) **All-period GT-slot availability** = GT slots (every labeled period) with a stored Layer 2 prediction of the same full semantic identity (fiscal year/period type included, attribution mapped through the key map) / eligible GT slots. (c) **Layer 1 comparative capture** = comparative-period GT occurrences with a `report_tagged_facts` row of the same expanded concept and context period / eligible comparative occurrences (`parse_status: ok` with concept, period and value present), with the value-correct share separately. Sensitivity removes every slot and prediction that went through a `contract_normalized` rule (recorded as `normalized_by` ids) and recomputes recall and strict precision. Zero denominator → "not measurable". **Labeled-capability recall** = matched / all eligible labeled GT slots of the event regardless of the panel or the scoring bucket (current, comparative, other-language, unresolved-language alike). Eligible verification states are `machine`, `second_read`, `adjudicated`; `unverified` (incl. an `unknown` basis) and `machine_v1` rows leave every denominator and their attributable predictions are out of scope; their counts are pinned. Slots are derived only from occurrences whose dimension set is empty or the attribution axis alone; other dimensional occurrences are evidence only.
6. **Regression rule — keyed, zero loss, prediction counts unfrozen.** The private run writes keyed outcomes per slot; the per-issuer baseline is the **last promoted** keyed baseline (`make realdata-esef-promote`, an owner action), bound to the frozen `gt_version`, `key_map_version`, `normalization_version` and corpus `registry_hash`. The public `realdata-esef-baseline.json` pins those equality fields plus `events`, `floor_events`, `issuers`, `gt_slots`, `unverified`, the `matched` floor, and ceilings on `previously_correct_slots_lost` (hard 0), `false_positives`, `zero_output_events`. The ratchet fails on any lost previously-correct slot (individual matches preserved — offsets are not allowed, owner decision), on false positives above the ceiling, on a non-finite metric; an equality mismatch is "incomparable — rebaseline required" (exit 2), never a pass; an improvement exits 2 as a stale baseline pending promotion. Intervals are printed as descriptive counts only; a fixed panel needs no confidence interval.
7. **Sampling frame — output-independent, by bytes and filing evidence.** `build_frame.py` inventories the pinned snapshot's fetched documents for the acceptance issuers (testing.md § Acceptance corpus) by reading the bytes (ZIP → every member; iXBRL sniff; financial-statement contexts), classifies the reporting event from the filing (primary-statement contexts, duration months → annual/interim, basis from package path → cover page → `unknown`, language from `xml:lang` → filename → `unknown`), queues every `unknown` for a filing read, selects the newest annual + newest interim per issuer as the **initial fixed regression panel** (PL `floor`, EN `twin_diagnostic`, package over loose instance, corrections as vintages, deterministic tie-breaks), persists the inferred fiscal calendar per event (used for every occurrence, instants included), keeps eligible-but-unparseable filings and members in the frame (labeled, `unverified`, or queued — so they count), and never reads an extraction result table. A file with no iXBRL instance is never an event.
8. **Blinded adjudication** follows `scripts/realdata/esef-v2/LABELING.md`: the first reader is the blind reference parser; the second reader (human offline or an external agent the owner runs) answers indistinguishable tasks — all disagreements plus a seeded, frozen 10 % agreement sample — from the filing bytes only, sealed before any compare; the app's value is never an input; task files, the task index and the ground-truth/occurrence files are bound by one hash lock that every seal and the compare re-verify (the compare checks every locked task file and every seal registered in `seals.lock` — a missing, altered or unregistered seal aborts it), an invalid answer fails the whole compare with no partial write, and a contradicted machine label without filing evidence becomes `unverified`; a systematic error found in the agreement sample re-reads the whole class before any floor is pinned. Imported v1 rows live in a separate reference artifact unless explicitly mapped to frozen events.
9. **Wiring stays advisory** (ADR 0096): `make realdata-esef-score` (diagnostic) and `make realdata-esef-check` (required mode: nonce-named metrics artifact that must exist after the harness ran, then `realdata-ratchet.mjs --profile esef`), owner-machine only; the engineering-workflow advisory table, the Definition of Done ("ran `realdata-esef-check` when touching the ESEF path, or recorded why not applicable") and the epic-closure audit list reference it. The #182 scorer stays as the **stored-state audit** (zero-pdf assertion).
10. **Hermetic proof in CI**: a synthetic sample corpus (`src-tauri/testdata/esef-v2-sample/`: PL floor + EN twin instances, a standalone package member, its own measured baselines) drives the harness through the real job; altered bytes with unchanged GT change the outcome (freshness), mismatch classes are scored not normalized, EPS equality is exact, a zero-output event counts in recall, a within-issuer offset fails the ratchet, the metrics text carries no content. Python tooling (stdlib only; `python3` added to the nix dev shell for the unit checks) is tested on synthetic bytes.

## Consequences

- Sound floors exist only after PR-B's measurement on the owner's machine; until then `realdata-esef-baseline.json` is `unmeasured` and the ratchet refuses to judge it.
- The interim-as-FY derivation is a measured defect the first run will surface; it is carded, not hidden by the frame.
- **The initial panel is annual-only** (first frame build on the 2026-09-10 snapshot): every ESEF filing of the acceptance issuers is an annual ZIP package (one per issuer, 23 issuers; ALE/CRI/CRQ have none, EXC is EBI-only); GPW interim reports are PDFs, never iXBRL, so the interim leg is empty by construction and the manifest says so per issuer. The ~920 loose `.xhtml` files fetched alongside (board letters, auditor opinions, management and ESG reports) carry no iXBRL and are never events — counted, not queued.
- The v1 corpus remains a stored-state audit input; its rows enter v2 only as `machine_v1`.
- Any change to the key map, the normalization list, the GT or the corpus bumps `measurement_version` and requires a deliberate rebaseline — the ratchet never silently accepts a moved denominator.

## Rejected

- Document-level estimand or collapsing language twins (double counting; no equivalence the app has).
- Issuer replay as the primary floor (#331 asks for fresh extraction; replay stays a diagnostic).
- Percentage or macro-average floors with tolerance (offsetting regressions hide behind aggregates).
- The production `Tolerance` as the equality rule (EPS 0.10 vs 1.00 would match).
- Reusing the v1 merged ground truth or `gt182_app_comparable_key` as the v2 contract (dimensions discarded, owners rows mis-mapped).
- Selecting the frame through production period derivation (conditions the frame on a component under test).
- Scoring the aggregator tier (no offline corpus; a different estimand).
