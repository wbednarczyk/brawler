# ADR 0077: Trusted Extraction Foundations — Document Taxonomy, Coverage Map, History Sweep, Free-Tier Vision Fallback

Status: Accepted (2026-07-08) — G0 verdict: hybrid (owner, 2026-07-08; evidence section below)

Realizes the tier-4/last-resort layer of [ADR 0061](0061-deterministic-fundamentals-data-gathering.md) and the automation its trust goal implies. Amends [ADR 0055](0055-structured-fundamentals-extraction.md) (extraction stays deterministic-first; adds the doc-kind taxonomy and canonical-report selection), [ADR 0060](0060-ai-capability-routing-and-openai-compatible-provider.md) (adds a vision-extraction capability; drops the Gemini-for-documents premise as the only option), and [ADR 0036](0036-ai-kpi-extraction.md) (the AI-confirm path must validate; `validation_status='none'` is retired from every AI path). Execution detail: [docs/plans/trusted-extraction-foundations.md](../plans/trusted-extraction-foundations.md).

## Context

Owner verdict after v0.50 T7 real validation (2026-07-08): the qualitative-assessment support is trusted; **extraction of data from reports is not**. Concretely: of ~242 documents for one company only ~10% plausibly contain extractable data and nothing marks them; after a backfill nothing runs extraction (the user clicks per document); some documents fail to extract with no map of what is missing; AI-extracted facts bypass validation entirely (`validation_status='none'`) while deterministic facts pass accounting-identity checks — an inverted trust hierarchy. The acceptance journey is literal: *add LPP → click Backfill → result reports are automatically processed, data extracted and visible in the panel.*

Constraints: free AI tiers only (owner decision — paid APIs rejected); PDF rasterization is impossible in v1 (pure-Rust cross-build, ADR packaging constraint); refresh-time autopilot deliberately processes only the newest document per type and must stay that way.

## Decision

1. **Document taxonomy.** `report_documents.doc_kind` ∈ `periodic_ssf | periodic_jsf | auditor_opinion | presentation | governance | other` (nullable = unclassified), classified deterministically from title/filename by `classify_doc_kind`; `classify_statement` is reimplemented on top of it so the two cannot drift. A pure canonical-report-per-period function picks ssf over jsf, newest revision.
   - *Amendment 2026-07-09 (owner-approved):* an ESEF `.xbri` **package** is the periodic filing itself, not a companion — a bare package with no ssf/jsf marker classifies `periodic_ssf` (default-consolidated). `.xbri` is therefore removed from the companion-extension denylist; a `.xbri.xades` **signature** stays `other` because the `.xades` companion check runs first. The report diff cannot compare a package (or zip) body, so `report_diff::classify_statement` keeps a projection-side exclusion (`.xbri`/`.zip` → `None`) — a **diff capability limit, not a taxonomy change** — documented and unit-tested there, leaving the diff's `classification_corpus_golden` unchanged as the no-regression proof.
2. **Coverage map as a computed read model** (no new table in v1): per company, periods from reports ∪ periods with facts, each cell reporting has_report / has_facts+validation / review_state / skipped_budget. The map is the honest answer to "what do I have, what is missing, and why".
3. **History sweep as a durable job**, chained from the end of `run_backfill` and available manually: enqueue extraction for every canonical periodic report whose period lacks accepted facts, through a shared `enqueue_extraction_run` also used by the existing detection sweep. Refresh-sweep semantics unchanged.
   - *Amendment 2026-07-09 (owner-approved):* (a) the sweep enqueues **full autopilot runs** through the shared `enqueue_extraction_run` with `trigger='history_sweep'` — one deterministic run id per `(company, document)`, dedup + dce9ce8 re-arm identical to detection; the `autopilot_run.trigger` CHECK gains `'history_sweep'` in migration 0062 (T3.2), so until then only `'detection'|'manual'` are storable. (b) Sweep-triggered runs are **deterministic-only until F3b**: `stage_extract` must not fall back to the text-AI `kpi_extraction` path for `trigger='history_sweep'` (the tier-4 budget counter, T5.2, does not exist yet — running unbounded AI over a whole backfill violates the G-4 budget-stop spirit); the gating itself lands in T3.2. (c) **Trust ladder:** a sweep (chained or manual) runs only for mode ∈ {`assist`, `autopilot`}; a company in mode `off` ends the sweep with an explicit `skipped_reason='automation_off'`, never a silent skip.
   - *F6a annotation 2026-07-10 (best-extractable candidate, T-A2):* the sweep candidate is the period's **best extractable document**, not blindly the coverage canonical. When the canonical is a non-iXBRL XHTML (a pdf2htmlEX render — extractable by no deterministic tier and ineligible for the PDF-only tier-4), the sweep attacks the period's next-best fetched periodic document that IS potentially extractable (a PDF, or an iXBRL `.xhtml`/`.xbri`/`.zip`), preferring ssf over jsf then the newest; a period with only the non-iXBRL XHTML still enqueues it so the run records the honest `not_pdf` delta (never a silent drop). This is a **sweep-layer fallback only** — the canonical selection (§1 / ADR 0061 dec. 1b) is unchanged. Period derivation (`derive_report_period`) now falls through from a failed iXBRL self-derivation to the title/URL parse (T-A1), so a non-iXBRL XHTML classifies its period like a PDF.
   - *Amendment 2026-07-18 (v0.57 fix wave 2 — backfill is automatic for automated companies):* the report-history backfill was manual-only (one caller: the `backfill_company_history` IPC command), so a tracked company whose reports were never fetched sat permanently empty — the owner's live DB had 33/50 tracked companies with zero fetched periodic reports despite all 50 being `mode='autopilot'`. **Trigger parity added:** `enqueue_company_backfill_catch_up` enqueues a durable `company_backfill` job (sources lane, serialized on the Bankier-company source lock) for every **automated** company (`mode != 'off'`) with **no fetched periodic report** (`companies_lacking_periodic_coverage`), wired at **app startup** and **after every successful source refresh** — the same catch-up parity the ownership / management-holdings extractions already have. Idempotent by the coverage predicate + a stable per-company job id (INSERT-OR-IGNORE), so a queued/running/completed backfill (or a genuinely empty issuer) is attempted once, never re-fetched every refresh. A `mode='off'` company is skipped with an explicit logged `automation_off` reason (§3 amendment (c) idiom — never a silent skip). Pacing is the ADR 0059 queue serialization; no extra per-pass cap needed.
   - *F3b annotation 2026-07-10 (T5.2+F3b landed):* amendment (b) is **lifted** — the §6 budget now governs. A sweep-triggered run whose deterministic pipeline does not emit enters tier-4 exactly like a detection run **iff** one unit of its sweep's snapshotted budget is granted (`enqueue_extraction_run` gained a `sweep_id` param threaded onto `autopilot_run.sweep_id`, migration 0065); a denied unit — budget exhausted, or a legacy run with no `sweep_id` — records `{ extractionAvailable: false, reason: "skipped_budget" }` on the run, never a silent skip. A deterministic Accepted outcome returns before the gate and spends nothing (§6 decision 4). The retired text-AI number-reading fallback stays retired for every trigger.
   - *F6b/T-B2 annotation 2026-07-10 (positional sub-tier productionized; owner GO):* the spike positional parser (`fundamentals::extraction::html_positional`) for **pdf2htmlEX visual-render XHTML** (interim statements published with no `<table>` and no `ix:` tags — CD PROJEKT among GPW issuers) is wired into routing.
     1. **Tier + provenance.** Positional facts persist under the existing deterministic `source_tier='pdf'` (the render is a visual-PDF reconstruction) with an identifiable `extraction_method='html_positional'` marker on `financial_facts` — **no new `SourceTier` variant**, so the trust-order enum is unchanged. `extraction_method` is a sub-tier label only, never trust-bearing; `source_tier` + `validation_status` remain the trust signals, and the set clears the **same** `validate_parsed_set` identity gate as every tier (never `validation_status='none'`; G-1 enumeration extended). Rejected: a dedicated `StructuredXhtml`/new tier variant (would perturb the trust order for a tier that is deterministically weaker than tagged iXBRL).
     2. **Current-period column = YTD cumulative** (owner convention). Column selection is now **automatic per row**, not a caller-supplied index: measurement on the 3 real CDR interims showed two 4-column layouts coexist and both interleave `[current, prior, current, prior]` — a main P&L/CF statement `[Q3-3M | prior-3M | 9M-YTD | prior-YTD]` (YTD at index 2) and the regulatory "Selected financial data" summary `[YTD-PLN | prior-PLN | YTD-EUR | prior-EUR]` (YTD-PLN at index 0). The current-YTD-PLN is the **larger-magnitude of the current family `{0,2}`** (9M > quarter; PLN > EUR). Rejected: a fixed index-2 (mis-reads the summary rows, which win the first-match for most metrics, as their EUR column) and preferring the summary table (needs fragile region-detection + detached-label clustering for the one metric, revenue, whose summary label is a separate positioned div). Result: **33/33 recall + precision** on the CDR ground truth (was 32/33 with a global column); the `realdata` ratchet floor promoted **0.90 → 0.99** (G-3). Known limitation: a mid-year sign reversal leaving |3M| > |9M| would mis-pick the quarter column — rare, caught downstream by the identity gate / the planned aggregator witness (BiznesRadar card under ad9d24f), deliberately not patched with column-summing (composites are a product decision).
     3. **Routing.** In `run_structured_extraction`, a bare XHTML that is **not valid iXBRL** (sniffed by the now-shared `esef::is_inline_xbrl`, a single source of truth with the sweep) routes to the positional tier instead of falling through the ESEF tier as not-extractable; `.xbri`/`.zip` packages stay on the ESEF package path. Tier-4 is never invoked for the render (not a PDF), so a sweep run degrades `not_pdf` upstream and spends **zero** budget (consistent with §6's static-ineligibility rule).
     4. **Sweep semantics (deliberate contract change from F6a T-A2).** `document_is_extractable` (`jobs/history_sweep.rs`) now counts a non-iXBRL XHTML as extractable via the positional tier; the T-A2 PDF-sibling fallback fires only for a **genuinely dead** canonical (unreadable or zero-byte file), never for a live non-iXBRL render. T-A2's tests were updated in place to assert the reversal (the non-iXBRL canonical is now kept over a PDF sibling; a zero-byte canonical still falls back).
   - *Terminal-run re-arm on capability upgrade (deliberate rule change, 2026-07-10, live MDV):* the sweep-enqueue dedup was permanently blind to any capability upgrade. `enqueue_extraction_run`'s `DedupedTerminal` decision skipped **every** existing terminal run, so once an earlier pipeline version finalized a run `succeeded` with `{ extractionAvailable:false, reason:"not_extractable" }` (e.g. the CDR interim XHTMLs, before the T-B2 positional tier existed), no later sweep could ever re-attack that document — the tier-3b positional tier made 9 CDR periods newly extractable yet a live sweep reported "Wydobyto 0 · pominięto 9". **New rule:** a terminal **succeeded** run whose `kpi_delta_json` records `extractionAvailable:false` with a re-arm-class reason is **re-armed** (reset to `pending`/`fetch`, re-stamped with the current `trigger` + `sweep_id`) so `stage_extract` runs again, iff the document is **now extractable**.
     - **Re-arm class + gate.** `not_extractable` / `not_pdf` / `no_stored_file` (couldn't-extract verdicts) re-arm **iff `document_is_extractable` is now true** (reused, not duplicated); a still-dead file (unreadable/zero-byte) stays deduped — no per-sweep re-parse loop. `skipped_budget` is **included** in the class: a budget-denied run is also terminal-succeeded, so without this rule a period the last sweep skipped for budget is permanently blind — a **fresh sweep carries fresh budget and must retry it** (the new sweep's own `ai_call_limit` still caps how many periods actually re-invoke tier-4, G-4, so this cannot runaway-spend). `no_vision_provider` is **included but additionally gated on a configured `VisionExtraction` provider** (the cheap `has_vision_provider` settings check the extractability test cannot see): re-arm only once a provider exists, so a period nothing can yet OCR is not re-armed every sweep.
     - **Excluded.** A run that **emitted** facts (`extractionAvailable:true`), and any `partial`/`failed` run, are never re-armed — the finished-report dedup survives. A run re-armed for `not_extractable` whose determinism still cannot derive a period re-records `not_extractable` and will be re-attacked next sweep (deterministic, budget-free); this is deliberate and matches `document_is_extractable` being the single extractability contract shared with candidate selection.
4. **Vision tier-4 behind determinism, inside the job layer** (`jobs/structured_extraction.rs`, never in pure `pipeline.rs`): runs only when determinism ends Flagged|Empty and budget remains. Its output passes the **same** `validate`/`validate_tier` as every other tier; validated facts persist as `source_tier='ai'` with a real validation status, unvalidated output becomes proposals for the existing confirm flow. `validation_status='none'` is banned on all AI paths, including confirming a proposal.
   - *F6a annotation 2026-07-10 (degrade log trail, T-A5):* every tier-4 degradation leaves a **production-visible trail** — one `log::warn!` per degrade (surfaced in Diagnostics → Logs) carrying the reason, `company_id`, `report_document_id`, the OCR markdown length when an OCR response already exists at that point, and a ~200-char prefix of the LLM response for `bootstrap_failed` (the JSON that failed to parse). The logger redacts message strings via `redact_text` (masking only sensitive `key=value` tokens), so the response prefix is safe to log. A period no longer degrades silently.
   - *Kickoff-decision annotation 2026-07-10 (T4.1 substrate — Mistral OCR + pure parser + OCR profile; no pipeline hook yet):*
     1. **OCR profile is its own table + type** — `company_ocr_extraction_profile` (migration 0063) + `OcrExtractionProfile` (`fundamentals::extraction::ocr::profile`). Rejected: extending the tier-2 `ExtractionProfile` (OCR markdown has a different `template_hash` and drift semantics — a `Nota` column, a value-column layout, an enumerator convention) and nesting the OCR layout inside the tier-2 `profile_json` (muddies the versioning of two independent learning loops).
     2. **Tier-4 facts persist `source_tier='ai'`** with a real (non-`'none'`) validation status; the OCR-vs-text-LLM mechanism is recorded in the provenance `citation` (the normalized OCR label the value was read from). The pure parser (`parse_ocr_markdown`) is tier-agnostic — the caller (T4.3) passes the tier — so the substrate encodes no trust decision.
     3. **Bootstrap emits proposals only.** The text-LLM bootstraps the profile once per company (it reads *labels*, not *numbers* — the spike showed fabrications come from the LLM reading values); that run's output and any low-confidence parse land as proposals for the existing confirm flow. The profile is confirmed on the first proposal confirmation (`OcrExtractionProfile::confirm` bumps the version); every subsequent document parses deterministically to facts that pass `validate`/`validate_tier`.
     4. **The tier-4 hook (T4.3) takes an explicit caller gate.** `manual`/`detection` triggers are allowed; `history_sweep` is denied until F3b (per §3 amendment b — no tier-4 budget counter exists yet). The T5.2 budget counter (`history_sweep_ai_call_limit`) plugs into that gate without changing the hook shape. None of this lands in T4.1: the substrate is pure/provider code with no pipeline wiring.
5. **Provider chosen by measurement, not preference.** A spike over hand-labeled real CBF quarterlies (double-pass ground truth) measures three free-tier shapes — Mistral OCR→parser, Mistral OCR→text-LLM, Gemini native-doc — on the residue determinism leaves, plus real free-tier limits. Proposed bar: post-validation precision ≥ 0.98, recall on residue ≥ 0.80. No numeric verdict → tier-4 is descoped and the coverage map shows the residue honestly (an acceptable outcome).
6. **Cost control v1 = call counter**: `history_sweep_ai_call_limit` (default 30 per sweep, 0 = off) enforced with visible used/limit progress; budget exhaustion marks periods `skipped_budget`, never a silent skip. `backfill_years` becomes a setting (default 3, 1–10).
   - *Implementation decisions 2026-07-10 (T5.2, owner-approved):* (1) the budget **unit is one tier-4 invocation** — the OCR + optional bootstrap-chat bundle for one document — never per HTTP request; (2) the limit is **snapshotted onto the sweep row at creation** (`history_sweeps.ai_call_limit`, migration 0065), so a mid-sweep settings change never moves an in-flight sweep's gate; (3) consumption is a single **atomic guarded UPDATE** (`... SET ai_calls_used = ai_calls_used + 1 WHERE id = ?1 AND (ai_call_limit = 0 OR ai_calls_used < ai_call_limit)`; `changes() == 1` ⇔ granted, `0` = unlimited), so concurrent runs can never over-spend the last unit; (4) **deterministic outcomes never consume** — only entering tier-4 spends a unit (the gate charges intent-to-invoke, keeping the counter an upper bound on provider calls). The setting clamps to `[0, 500]` on read and write (`backfill_years` posture).
   - *Budget-semantics refinement 2026-07-10 (F3b live validation, MDV):* the unit is charged **before** the invocation but only for a document a provider invocation could actually reach. **Static ineligibility is a pre-check that never spends** — no configured `VisionExtraction` provider, no stored file, or the ESEF/iXBRL route (tier-4 is PDF-only). `stage_extract` decides these cheaply *before* `try_consume_sweep_ai_budget` (mirroring the no-vision-provider pre-check), so such a run degrades honestly (`no_vision_provider` / `no_stored_file` / `not_pdf`) and spends **zero** units. This supersedes decision (4)'s earlier "a degraded tier-4 attempt … still spends" for statically-decidable degrades: a unit is an upper bound on *reachable* provider calls, not on configuration/format checks — charging them would burn the whole sweep budget on documents no invocation could read and mislabel later periods `skipped_budget`. A degrade discovered only *inside* the invocation (e.g. a transient error mid-OCR) still consumed its unit. The equivalent checks inside `run_tier4_extraction` remain as defense in depth.
7. **Pacing repair**: transient provider failures (limit/unavailable/network) propagate as job errors so the queue's capped exponential backoff engages; terminal failures keep fast-failing with their error code.
8. **Never repaint company-reported KPIs** (owner decision, 2026-07-08, ground-truth pass 2): a company-specific reported measure (e.g. CBF's non-IFRS "EBITDA Operacyjna") is never stored under a generic catalog key it doesn't equal — companies characterize themselves by their own KPIs, and the app must preserve that identity. The substrate exists (`kpi_definitions` with `scope='company'`); the extraction/UI feature work (company-characteristic KPI surfacing, one-off "*" annotations on facts) is tracked as separate backlog cards, and every extraction tier in this epic (including tier-4) must respect the no-repaint rule.

## Consequences

- The owner's trust question gets a measured answer: recall/precision on real labeled reports, pinned as a ratchet test (`realdata-extraction-metrics`) that reddens on regression — the same enforcement pattern as coverage and byte budgets (ADR 0038).
- One validation regime for all fact sources ends the deterministic-vs-AI trust asymmetry; the confirm flow becomes the only door for unvalidated numbers, and it validates on confirm.
- Backfill becomes the single user action for new-company data; per-document clicking remains available but optional.
- Guardrails harvested with the epic: G-1 no `'none'` on AI paths · G-2 taxonomy contract test · G-3 real-data ratchet · G-4 budget-stop · G-5 capability roundtrip · G-6 rasterization ban (rule + checklist).
- Free-tier-only means tier-4 may be descoped by evidence; the deterministic pipeline plus the coverage map still close gaps 1–2 on their own.

Mistral free-tier limits observed (19 calls total, zero 429/503): OCR `625 pages/min` (a 14-page statement ≈ 14); chat `50 req/min` and `50k tokens/min` (binding) → ~3–5 doc-extractions/min depending on prompt size. OCR v4 returns tables separately in `pages[].tables` — consumers must stitch them into the markdown (unstitched output scores 0).

Additional structural findings: CD PROJEKT publishes **no** interim-statement PDF (ESEF XHTML only; the only PDF is a 2-page ESPI form) — a PDF-native tier-4 structurally cannot cover such issuers and the ESEF tier must (confirms tier-4 as complement, never replacement). The spike also surfaced a live-DB ingestion bug (XHTML stored as `.pdf` + foreign-issuer attachment associations) — tracked as its own bug card.

**Verdict (G0, owner, 2026-07-08): hybrid.** Gemini rejected (unreliability confirmed by measurement; free quota of 20 requests/window cannot carry a sweep). Tier-4 ships as Mistral OCR + a **per-company OCR-extraction profile**: the text-LLM is used once per company to *bootstrap* the profile (label map, value-column layout, scale — the spike showed fabrications come from the LLM reading numbers, not from mapping labels), then the deterministic parser reads every document through that profile; profile proposals and any low-confidence output land as proposals for confirmation, and everything passes `validate`/`validate_tier`. This instantiates ADR 0061's per-company versioned extraction-profile philosophy at the OCR tier. Scale is a first-class profile field (issuers print mln / tys. / full PLN — a wrong scale assumption mis-states values 1000× silently; magnitude cross-checks against prior periods guard it).
