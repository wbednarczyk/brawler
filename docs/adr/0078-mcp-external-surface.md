# ADR 0078: External Surface — Read-Only MCP Server MVP (NS1 Slice 1)

Status: Accepted (2026-07-11, owner sign-off)

Realizes slice 1 of the **NS1 "Talk To Your Research"** north star ([roadmap](../roadmap.md#north-star-talk-to-your-research-mcp)), pulled forward by owner decision (2026-07-06, epic `6ed8ad1`). Applies [ADR 0039](0039-ports-and-adapters-posture.md) (second driving adapter over the typed command layer), [ADR 0042](0042-advisory-verdict-port-and-open-core-boundary.md) (advisory gating unchanged), and [ADR 0070](0070-typed-command-error-envelope.md) (typed error codes on the new surface). Execution detail: [docs/plans/v0.52-judgment-capture.md](../plans/v0.52-judgment-capture.md) stream M.

## Context

The app's domain (companies, facts, coverage, research, claims, quality assessments) is reachable only through the Tauri UI. The NS1 destination is a conversational surface over the user's **own** research; its precondition is a machine surface an AI assistant can call. MCP (Model Context Protocol) is the de-facto standard connector for local AI assistants (Claude Code/Desktop and a growing client set) — exposing MCP means assistants connect with zero bespoke integration.

Constraints: local-only (no cloud/egress — product rule), strict typed tools (no arbitrary shell/FS — Tauri permissions posture), pure-Rust shipped deps (cargo-xwin Linux→Windows cross-build; no `*-sys`/ring/openssl — the reqwest/native-tls precedent), conservative dependency posture, deterministic engine untouched, decision-support only. Command logic is already cleanly separable from Tauri: `#[tauri::command]` fns are thin wrappers over `AppState` domain-store methods, and the mock-fidelity harness drives the real `AppState` without a Tauri runtime — the seam this adapter needs already exists.

Evaluated for the protocol layer: **`rmcp`** (official Rust SDK) — upstream compliance and schema derivation, but pre-1.0 with breaking minor releases, pulls a proc-macro + schemars + axum/hyper server stack into the shipped binary for four read-only tools, forces async bridging over the blocking rusqlite `AppState`, and adds a cross-build feature audit to every upgrade. **Hand-rolled protocol subset** — a read-only tools server needs six JSON-RPC interactions; ~600 lines of pure serde functions, fully unit/property/snapshot-testable, one tiny HTTP dependency. Chosen: hand-rolled now with a recorded rmcp re-evaluation trigger (decision 8).

## Decision

1. **Second driving adapter (ADR 0039).** The MCP server calls only existing `AppState` read models / extracted pure command helpers — never SQL, files, or Tauri internals. No new port is introduced (no second implementation exists); tools bind directly to the domain stores.
2. **Transport: stateless MCP Streamable HTTP subset, in-app.** A dedicated `std::thread` runs a **`tiny_http`** server bound to `127.0.0.1:<port>` only (hardcoded loopback — no bind-address setting). Single route `POST /mcp` accepting one JSON-RPC 2.0 message per request, responding `application/json`; `GET /mcp` → 405 (no SSE stream in the MVP); JSON-RPC notifications → 202 with empty body; batch requests rejected (removed in the 2025-06-18 MCP revision); request body capped at 1 MiB; `Host` header validated against localhost forms (DNS-rebinding defense). No session state. Rationale for tiny_http over axum/hyper-server: three small pure-Rust transitives, synchronous handlers call the blocking `AppState` directly (no tokio feature changes, no `spawn_blocking` bridging), graceful stop via `unblock()`; axum is the recorded fallback if tiny_http's dormancy ever bites — the server is isolated behind `mcp/server.rs` so the swap is local.
3. **Protocol module: hand-rolled MCP subset, one place.** `src-tauri/src/mcp/protocol.rs` implements `initialize` (protocol-version negotiation, pinned supported revision), `notifications/initialized`, `ping`, `tools/list`, `tools/call`, and JSON-RPC error responses (−32700/−32600/−32601/−32602/−32603). The protocol layer lives **only in-app**; the stdio adapter (decision 6) carries no protocol knowledge.
4. **Auth: bearer token in the OS keychain, off by default.** The server starts only when the user enables it in Settings **and** a token exists. Token: 32 random bytes, hex; stored under the credentials boundary (`brawler/mcp/auth_token`, generalizing the existing `CredentialDescriptor` beyond AI providers); shown to the user **exactly once** at generation; compared constant-time via SHA-256 digests; never logged. Requests without/with a wrong `Authorization: Bearer` → 401. Lifetime: app-open-only (spawned in the `lib.rs` setup closure beside the scheduler); enable/disable takes effect live; bind failure or missing token surfaces in `mcp_status` and the Settings status pill — never a crash. Default port 8317, editable in Settings.
5. **Four read-only tools, strict schemas.** `get_company_dossier{company}` (identity + fundamentals coverage + confirmed facts slice + scorecard summary — composed from `lookup_company`, `compute_fundamentals_coverage`, facts reads, `fundamentals/scorecard.rs`), `search_research{query, company?, limit?}` (the FTS `search` read model), `list_claims_due{company?}` (`list_claims_to_verify`), `get_quality_assessment{company}` (qualitative assessment + framework evaluations). Inputs are typed structs with `#[serde(deny_unknown_fields)]`; the `tools/list` JSON Schemas are hand-written constants; an insta snapshot of the `tools/list` response is the **frozen tool contract** — changing the tool set or shapes is a reviewed spec change. Tool failures map onto the ADR 0070 code set. **Read-only guarantee:** tools call read paths only; adding any mutating tool requires a new ADR (tripwire).
6. **Thin stdio adapter, a dumb pipe.** `src-tauri/src/bin/brawler-mcp-stdio` reads newline-delimited JSON-RPC from stdin, POSTs each line to `http://127.0.0.1:<port>/mcp` with the bearer token (env `BRAWLER_MCP_TOKEN` or `--token`), writes the response line to stdout. ~120 lines over `reqwest::blocking` (already in tree). HTTP-native clients (Claude Code `--transport http`) connect directly and skip it.
7. **Advisory gating unchanged (ADR 0042).** Tool outputs are sourced facts, coverage, scorecards, and the user's own research — decision support; no buy/sell/hold phrasing is introduced on this surface, and the open-core advisory boundary is unaffected.
8. **rmcp re-evaluation trigger.** When NS1's conversational slice is taken up (resources/prompts/streaming/chat — after `v0.64.0`), re-evaluate adopting `rmcp` (or the then-current official SDK) for the protocol layer; the isolated `mcp/protocol.rs` module keeps the swap local. Until then, the pinned protocol revision + handshake snapshot + a named manual verification against a real client (Claude Code) in M5's DoD carry compliance.

## Consequences

- Assistants on the owner's machine can query his research with zero bespoke integration; the NS1 chat slice later builds on the same tools.
- New shipped dependency: `tiny_http` (3 small pure-Rust transitives); `getrandom` promoted to a direct dependency for token generation if not already present. Cross-build verified in M5 (`make package-windows-from-linux`).
- New external attack surface, mitigated: loopback-only bind, bearer token in keychain, constant-time compare, Host validation, body cap, off by default, app-open-only. Wire-level integration tests cover 401/403/405/413 and loopback-only behavior.
- We own protocol compliance for the subset (pinned revision, snapshot-tested handshake, real-client verification step).
- Guardrails: G-1 the `tools/list` insta snapshot freezes the tool contract; G-2 a mutating tool ⇒ new ADR (tripwire in the plan); G-3 token never in logs (review rule; the token value exists only in the keychain and the one-time reveal); G-4 loopback bind is not configurable.

## Open questions

- None blocking the MVP. Deferred to the NS1 chat slice: SSE streaming, resources/prompts capabilities, multi-client session management, rmcp adoption (decision 8).
